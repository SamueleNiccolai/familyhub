# F0 — Avvio

Settimane 1-2 · 19 ott – 1 nov 2026 · stima **16 h** · capacità 24 h (≈6 sessioni)

## Obiettivo
Vedere, entro la prima settimana, una lista servita dal MIO backend Spring Boot sullo schermo di almeno un telefono, ed entro la seconda su iPhone e Android. Zero architettura: è un «hello world» end-to-end che prova che il circuito funziona e che l'ambiente è pronto.

## Cosa saprò fare alla fine
- Creare e avviare un progetto Spring Boot ed esporre un endpoint REST.
- Creare un'app Expo, aprirla con Expo Go sul telefono e farle chiamare il backend sulla LAN.
- Leggere e scrivere il TypeScript di base che serve a un'app React, partendo da quello che so di Java.
- Usare il repo con Claude: `/sessione`, `/fatto`, `/bloccato`, `/chiudi`.

## Definition of done (verifica eseguibile)
- `cd backend && ./mvnw spring-boot:run` → `curl http://localhost:8080/api/items` risponde con JSON di 5 elementi.
- `cd backend && ./mvnw test` verde, con i test di «Java 21 in pratica».
- `cd mobile && npx expo start` → la lista appare su entrambi i telefoni (screenshot in evidenze).
- `git log --oneline` mostra ≥3 commit e `git log --format=%s | grep -Evc '^(feat|fix|test|chore|docs|ci)(\(.+\))?: '` restituisce 0.

## Teoria just-in-time (max 20 min per voce, solo quando il blocco la richiede)
- Cos'è un'app Spring Boot: `@SpringBootApplication`, auto-configurazione, starter, server embedded → Spring Boot reference, «Developing with Spring Boot», prime sezioni.
- Expo: cos'è Expo Go, cos'è Metro, perché serve l'IP LAN → docs.expo.dev, «Create your first app».
- TypeScript: tipizzazione strutturale, union, `undefined`/`null`, `type` vs `interface` — solo quello che serve alla `FlatList`.
- Niente altro. JPA, DB, test di integrazione, navigazione, styling: fasi 1 e 3.

## Trappole e punti di scoraggiamento
- `localhost` dal telefono non esiste: uso l'IP LAN del PC (`hostname -I`) oppure `npx expo start --tunnel`. Telefono e PC sulla stessa Wi-Fi.
- Expo Go degli store supporta un solo SDK. Se segnala incompatibilità, guarda chi è indietro: Expo Go vecchio → aggiorna l'app; progetto vecchio (succederà quando arriva Expo Go 58: oggi `create-expo-app` crea ancora SDK 57) → `npm install expo@^58.0.0`, poi `npx expo install --fix`.
- Expo Go su iPhone chiede il login: lo stesso account del terminale.
- C'è già un OpenJDK 25 di sistema: se `java -version` non dice quello che ho scelto, la shell non carica SDKMAN (zsh: init in `~/.zshrc`; aprire un terminale nuovo).
- Firewall Ubuntu (`ufw`) che blocca la 8080.
- Voler «fare bene» già ora (layer, DTO, DB): no. Due file, una lista, un telefono.
- L'ambiente che non collabora il primo giorno è normale: è la fase più «idraulica». `/bloccato` con il log esatto, non con «non funziona».
