# F1 — Spring Boot core

Settimane 3-7 · 2 nov – 6 dic 2026 · stima **50 h** · capacità 60 h (≈15 sessioni)

## Obiettivo
La lista della spesa vera: persistita su Postgres, con CRUD REST, validazione, errori ben fatti e una suite di test che gira in un comando. È la fase che vale di più nei colloqui: la mappa Java EE → Spring la costruisco qui. In parallelo, un allenamento corto e costante su Java, SQL e HTTP: le cose che i colloqui chiedono prima ancora di Spring.

## Cosa saprò fare alla fine
- Strutturare un'app Spring Boot per feature (controller → service → repository) con DI per costruttore.
- Usare Spring Data JPA, Flyway, Bean Validation, `ProblemDetail`.
- Testare a tre livelli: unit (Mockito), slice (`@WebMvcTest`, `@DataJpaTest`), integrazione (`@SpringBootTest` + Testcontainers).
- Spiegare a un colloquio cosa fa Spring «sotto»: bean, contesto, proxy, transazioni, profili.
- Rispondere con un esempio scritto da me su collezioni, Stream, concorrenza di base, JOIN e indici, semantica HTTP.

## Definition of done
- `docker compose -f infra/docker-compose.yml up -d` + `./mvnw spring-boot:run` → CRUD funzionante con `api.http`.
- `POST /api/items` con body invalido → 400 con corpo `ProblemDetail` (`type`, `title`, `status`, `detail`).
- Flyway applica le migrazioni su un DB vuoto; `ddl-auto=validate` non si lamenta.
- `./mvnw verify` → BUILD SUCCESS, ≥15 test oltre ai kata, ≥1 con Testcontainers (Docker avviato).
- I 4 kata sono verdi e l'`EXPLAIN ANALYZE` prima/dopo l'indice è in evidenze.

## Teoria just-in-time — mappa Java EE → Spring
- `@Inject` su campo → constructor injection (immutabilità, testabilità, niente proxy magici).
- `@Stateless` + transazioni container → `@Service` + `@Transactional` (proxy, propagazione, rollback di default solo su unchecked).
- JAX-RS (`@Path`, `@GET`) → Spring MVC (`@RestController`, `@GetMapping`, `ResponseEntity`).
- JPA uguale (`EntityManager` c'è ancora); Spring Data aggiunge i repository e i query methods.
- `persistence.xml` / DataSource JNDI → `application.yml` + auto-configurazione; profili al posto delle build separate.
- Spring Boot reference: capitoli «Web», «Data», «Testing» — solo la sezione che serve al blocco.
- Testcontainers: testcontainers.com → guides → «Getting started with Testcontainers for Java» + la guida Spring Boot + Postgres.

## Trappole e punti di scoraggiamento
- La «magia» di Spring frustra chi viene da Java EE: quando non capisco chi crea cosa, `/bloccato` subito, non dopo due ore di debug.
- Over-engineering: hexagonal, mapper, 7 layer. Un package per feature, tre classi, basta.
- Testcontainers vuole Docker avviato e il mio utente nel gruppo `docker`.
- `@SpringBootTest` per tutto → suite lenta. Slice test dove basta.
- `ddl-auto=update` «perché è comodo»: no, Flyway è la regola anche in locale.
- Tutorial e corsi su Boot 3 (quasi tutti): in Boot 4 `@MockBean` → `@MockitoBean`, `spring-boot-starter-web` → `spring-boot-starter-webmvc`, `@WebMvcTest` / `@DataJpaTest` richiedono `spring-boot-starter-webmvc-test` / `spring-boot-starter-data-jpa-test`, Testcontainers 2 usa `testcontainers-postgresql`.
- Kata che diventano un corso di Java: 1 h, un test, una spiegazione. Basta.
